# 心动挑战实现与验收

参考根目录的 `AI真心话大冒险_高互动提示词与验证样例(1).md`、`zxh方案.txt`。

## 统一约定

- 以两份文档共同采用的完整流程为准：一次生成整把 1 / 2 / 4 轮，逐轮播放；自由互动和结局分别调用。格式错误允许修复，不按抽卡临时生成。
- 每轮每名 NPC 一张固定牌，USER 两张真心话、两张大冒险，每张都有完整分支。牌背显示实际候选数量，不为凑三张重复牌。
- USER 是行动顺序中的一员，不在全员结束后额外行动一次。
- NPC 的卡、答案与对象固定；换牌只用于 USER。USER 可拒绝，两种牌型均可选择；不把拒绝当失败。
- AI 不生成好感分数。程序记录实际互动次数、共同经历、边界与记忆；关系变化通过已发生的剧情体现，避免默认升级关系。
- 数字相同时，距离相同者按最初席位顺序排列。数字和最终顺序在动画前保存。
- 旧分支保留供回看，不进入后续生成的有效记忆。回放不会修改游玩状态。

## 验证方法

纯状态测试覆盖：格式校验、条件和来源筛选、确定性抽卡、命运排序、选择分支、自由输入汇合、拒绝、完成屏障、恢复、重开与历史、有效记忆、存储异常。

浏览器检查覆盖：手机与电脑布局、键盘可达性、长文本与菜单、设置至结局的完整模拟流程、刷新恢复和取消请求。真实模型质量取决于所选模型；未使用用户 API 进行付费请求时须明确说明。

```sh
node --test tools/test-heart-challenge.mjs tools/test-heart-world.mjs tools/test-heart-prompts.mjs tools/test-watermelon.mjs
node tools/check-heart-challenge-browser.mjs
```

浏览器脚本使用独立 Chromium 临时配置和模拟模型输出，不读取用户浏览器资料，不调用付费 API；覆盖实际 Canvas 的落子、合成、暂停、恢复和退出清理。

## 世界配置与交互

- 世界配置与小屋设置共用字段映射；角色卡自动来源读取完整卡片，手动来源只注入手动描述。关闭的资料保留在编辑存档内，不进入请求。
- 懒人模式读取当前用户设定、完整角色卡和蓝灯/绿灯条目，与小屋设置一致，不额外开启聊天或语言选项。
- 最新聊天按宿主设置读取最近 8 条；已有预设保留其快照，匹配当前角色时可刷新。世界书支持蓝灯、蓝灯加绿灯、手动选择；刷新保留手动勾选。
- “你的称呼”独立保存，重新读取人设、角色卡或世界来源不覆盖已填写的称呼。“补充信息”始终是最后一个编辑字段。
- 完整的已启用世界资料、称呼和补充进入开局、自由回复、结局三类请求；前置提示词及特殊语言要求同时位于请求正文前部。不携带 API 密钥与头像。
- 保留旧世界背景和角色资料的迁移兼容，不对长世界描述静默截断；异步读取不能覆盖之后的手动选择，也不能串入其他房间。
- 页面仅保留功能标题、状态和必要说明；移除装饰性口号。剧情风格、轮数和顺序直接可见，角色、牌库和连接设置分组展开。
- 选项保留上一句角色对白；自由输入单独展开，追问状态自动打开回复框。空格/回车只推进阅读，长按不跳句，Ctrl/Cmd+Enter 发送回复。
- 菜单阻止背景交互并管理焦点；小屏输入时压缩次要信息。取消生成可重新安排，结束最后一次行动后直接结算，明细与重玩按需展开。

## TXT 提示词

运行时读取 `assets/heart-challenge/text/` 下的 `system.txt`、当前任务的 `game.txt` / `reply.txt` / `ending.txt`，以及对应的 `*-repair.txt`。详细编辑说明在该目录的 `README.md`。

每次生成或手动重试使用 `cache: no-store` 重新读取；一次任务的自动修复复用同一批文本。加载支持取消，缺文件、空文件、HTML 错误页或缺失必需占位符时停止，不调用模型，也不回退到内置提示词。JS 仅负责数据组装、占位符替换和程序校验，正文和修复要求都由 TXT 提供。提示词按任务目标、输入界定、规则、数量、标签、示例、检查清单分模块；明确设定/有效事件/未来编排的区别和NPC知识边界。

测试覆盖模板更新生效、三类任务的上下文注入、修复版本一致、占位符不递归替换、读取失败和取消。浏览器回归还验证修改 TXT 后无需刷新页面即可手动重试，且读取失败不产生模型请求。

## 模型输出协议与检查顺序

整把生成严格采用参考文档的文本协议，不让模型输出内部 JSON：

```text
<cards>
card_id|round_id|turn_id|actor_id|T/D|标签|题目
</cards>
<story>
<open>单段开场</open>
<round id="R1">
<turn id="R1A1" actor="P1" card="R1A1C1">
[P1]选牌宣言。
[DRAW:R1A1C1]
...固定剧情、interact、option与匹配的continue...
[DONE:R1A1C1]
[END]
</turn>
<turn id="R1A2" actor="USER">
<pick T="R1A2C1,R1A2C2" D="R1A2C3,R1A2C4"/>
<case card="R1A2C1">...完整剧情、DONE与END...</case>
...其余三张完整case...
</turn>
</round>
</story>
```

检查按“协议结构 → plans绑定与题库来源 → 每张最短可播放路径总句数 → 选项与公共汇合 → USER自主权 → 1V1/多人覆盖 → DONE/END”执行。句数检查会一次列出全部不合格卡，而不是每次只报第一张；修复调用收到完整错误清单和上次全文，必须完整重写。自由互动采用 `<reply state="resume|wait" resume="continue ID">...</reply>`，程序解析后仍使用结构化存档和状态机播放。

## 游戏舞台、回放与牌库

- 游戏舞台保持固定尺寸：房间席位、卡牌或对白、操作区域分别适配电脑、手机竖屏与横屏。长对白、题目与说明分页，刷新保留文字位置，尺寸变化保留阅读锚点。
- 真心话使用月牙与植物插画，大冒险使用罗盘与星芒；牌面、抽题牌背、卡牌记录及命运签牌共用主题纸色和墨色。小屏卡面按可用空间切换横向布局，优先保证题目可读。
- 命运抽签：电脑横向铺开，手机分行网格，横屏紧凑排列。未揭晓显示锁定状态，揭晓显示数字、距离和顺位，六人无需滚动。
- 工具栏只保留设置、记录、牌库与当前阶段可用的互动。设置编辑当前房间；房名、头像、API 即时生效，世界资料、角色和玩法供下一把使用。
- 记录包含剧情回看与卡牌记录。剧情回看及本轮回放均为完整、可上下阅读的页面，无逐句按钮或正文翻页。先前各把按日期、轮数和游玩次数折叠，本次默认展开，可切换旧局及历史分支。
- 回放按每个实际行动分段，标题包含头像、姓名、轮次和牌型。电脑并排展示头像姓名与气泡，手机使用上下排列；旁白为普通段落，抽牌事件为插画小卡。回放不会选择、推进或改写当前局。
- 卡牌记录保留本把全部候选；正面显示题目，背面显示实际抽取者。未选候选明确标为尚未抽取，换出的牌保留抽取记录。
- 系统牌库全房间共用，内含常规、成人暧昧两套；可复制内置牌库或创建、编辑自定义牌库。两种题型各 2—200 道，每行一题，校验重复、长度和协议符号。每把保存题库快照，后续编辑不会改变正在玩的剧情。
- 角色表情使用 `[P1;😳]` 等标签；选项阶段延续前一句发言的表情。已载入的绑定试玩仅补齐匹配对白的表情元数据，保留原剧情和进度。
- 验证覆盖 320×568、568×320、390×844、844×390、1366×900，以及八种主题、长文完整性、历史折叠、自定义牌库持久化和房间设置。
