游戏图标将会给出，因为大小可能不一致，请压缩到和其他图标一样的大小并插入。
请严格按照下面顺序完成，不要直接跳到开发。全部思考完成后，根据你的思考内容完成全部开发，禁止跳过任何一个步骤。

# 先理解这个游戏

先搜索并分析现有同类游戏的：

* 经典玩法和核心规则
* 胜负、通关或对战逻辑
* 常见操作方式
* 常见计分方式
* 关卡或难度变化
* 常见道具
* 典型PC/手机界面布局
* 有代表性的游戏截图

优先参考成熟、经典、玩家容易理解的玩法。

不要简单照搬某一款游戏，而是提炼这个游戏最核心、最有辨识度的玩法。

先用一句话明确：

**“这个游戏本质上是：______。”**

例如：

* 连连看：限时寻找可连接的相同图块并清空棋盘。
* 21点：与对手比较谁能更接近21且不爆牌。
* 俄罗斯方块：通过排列下落方块消除完整横行并坚持尽可能久。

后续所有设计都围绕这个核心展开。

---

# 确定完整游戏循环

明确玩家从进入游戏开始，会依次经历什么。

必须具体到：

**点击什么 → 出现什么 → 系统判断什么 → 成功会怎样 → 失败会怎样 → 下一步是什么。**

写清楚：

* 游戏如何开始
* 玩家可以点击哪些东西
* 每个按钮具体作用
* 每次操作后的反馈
* 合法操作
* 非法操作
* 触发条件
* 一局如何结束

不要出现规则模糊或“根据情况处理”这样的描述。

---

# 详细计分规则

计分必须能够直接编程实现。

可包含：

### 基础得分

完成一次核心有效操作得到多少分。

### 额外奖励

根据游戏特点加入合理奖励，例如：

* 连击
* 操作速度
* 剩余时间
* 操作难度
* 精准操作
* 特殊组合
* 风险操作
* 完美完成
* 连胜

### 扣分

只有真正有必要时才设计。

### 权重
根据不同难度/道具使用情况等，可为分数分配权重。

### 关卡结算奖励

明确剩余时间、未使用道具、完美完成等如何计算。

### 分数结构

明确：

* 本局分数
* 本关分数
* 累计总分
* 历史最高分

分别什么时候增加、什么时候清零。

所有公式必须给出具体数字。

# 道具系统

参考现有同类游戏最常见、最容易理解的道具设计。

建议2～3个即可。

道具统一放在**主要游戏区域下方**，仿照当前其他游戏的道具按钮设计

每个道具必须明确：

* 名称
* 简单纯色图标
* 道具数量
* 什么时候可以使用
* 点击后立即发生什么
* 是否消耗
* 对分数/时间是否有影响
* 无法使用时的状态
* 用完后的按钮状态

道具应辅助核心玩法，不允许让玩家直接跳过整个游戏。

禁止依赖外部图片，道具图标使用Unicode、Emoji、CSS或SVG实现。

# 界面设计

先参考现有同类游戏截图，保留玩家熟悉的信息布局，再进行统一美化。

整体要求：

**简约、小清新、现代、干净，不复杂。**

不要过度装饰。

页面一个屏幕内完成游戏。

推荐结构：

### 顶部状态栏

放置核心状态

### 中央

游戏的核心操作区域。

必须占页面最大面积。

### 下方

第一层：

道具按钮。

第二层：

核心操作按钮（如果游戏需要）。

# PC和移动端同时适配

必须同时支持PC和手机。

### PC

* 游戏主体居中
* 设置最大宽度
* 鼠标点击反馈
* 游戏区域尽量完整显示

### 手机

* 适配游戏区域
* 按钮保证容易点击
* 核心操作按钮尽量靠近底部
* 不允许出现横向滚动
* 不允许重要内容超出屏幕
* 游戏元素较多时允许缩放、重叠或自适应排列

不要分别制作两个游戏。

使用同一个响应式界面自动适配。

# 九、动画与反馈

所有关键操作都必须有即时反馈。

例如：

* 点击：轻微缩放/高亮
* 正确操作：绿色反馈
* 错误操作：红色/轻微晃动
* 得分：`+100`上浮
* 连击：显示“连击 ×5”
* 发牌/移动：短距离滑动
* 消除：缩小淡出
* 成功：短暂强调
* 失败：轻微震动

单个动画一般控制在：

**100～500ms**

不要因为动画阻碍连续操作，如果是计时类等游戏，可动画过程中仍然可操作，尽可能保证游戏的丝滑。
尽可能让动画轻量，避免移动端卡顿情况，尽可能做好优化。

---

# char特殊语录

需要设计不少于6类特殊触发语录（除常规语录外）

语录必须与当前游戏行为有关，而不是随机说话。

例如：

* 玩家连续成功
* 玩家重大失误
* 极限操作成功
* 使用道具
* 时间快结束
* 玩家领先
* 玩家落后
* 玩家反超
* char失误
* char获胜
* 玩家获胜

尽量不要触发在游戏开始、结束部分，尽量可在游戏过程中多次触发。
如果触发可能性过于频繁（比如每次下棋触发语录），可以设置触发概率，或者触发间隔。

---

# 小剧场

根据游戏内容设计：*不少于5个“小剧场”。（除常规小剧场外）

例如可以来源于：

* 玩家连续极端操作
* 双方连续平局
* 玩家极限翻盘
* AI连续失误
* 玩家连续犯同样错误
* 极其幸运的随机结果
* 极其倒霉的随机结果
* 最后一秒通关
* 特殊隐藏组合
* 最终关特殊状态

# 日志记录

思考在日志记录的时候，输入什么信息可以最快理解整局游戏的状态和特殊的触发点，能够让char根据这一局游戏写出更符合实际的日志。例如道具使用次数、什么时候使用的，每一把如何完成的，多少次极限救场等等。

# 特殊状态处理

必须主动考虑并实现容易遗漏的情况：

* 连续快速点击
* 重复点击同一个对象
* 动画过程中继续点击
* 没有合法操作
* 随机生成无解
* 时间归零瞬间仍在动画
* 双方同时达到目标
* 平局
* 暂停
* 浏览器切换后台
* 手机屏幕尺寸变化
* 刷新页面
* 道具数量为0
* 多个事件同时触发
* 多个弹窗同时出现

为每种情况规定唯一处理方式，避免状态冲突，尽可能避免。
